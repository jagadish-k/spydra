## Deviations

- **The audit shell had no Docker.** It is a Linux VM with the repo mounted,
  so every containerised target was unavailable to the agent. The executable
  half of the audit therefore ships as `scripts/audit-phase0.sh` and was run
  by the human on the development machine; `make check` likewise. Each of the
  four commits was gated there before the next was made.
- **The harness had four bugs of its own, all found by running it.** Recorded
  because a verdict is only worth the harness that produced it: output was
  captured rather than streamed (a silent `make check` read as a hang); BSD
  `date` has no `-Is` and no `%N`, so two timers would have mismeasured
  silently; `sleep N` stood in for a readiness check and scored two sections
  UNPROVEN on a container that was merely slow; and 0.14 tested a guarantee
  the chain does not make (see Findings).
- **A second writer touched this branch.** `docs/adr/0025-ui-states-authority.md`
  and the `adr/README.md` row were written at 04:17 UTC by something other
  than the audit session. Reviewed line by line and adopted rather than
  replaced, with one correction (component count aligned to the corrected
  §3). Flagged because two writers on one branch is the case WORKFLOW §3
  calls not safe.
- **`spydra-reviewer` was not used as a subagent.** The role's adapters were
  not available as spawnable agents in the audit environment. The reading was
  done directly and kept read-only: no tracked file was modified during
  Part A, the four gate probes reverted in a trap, and `git status` plus
  `gen-agents.py --check` were verified clean afterwards. Stated rather than
  approximated, per AGENTS.md § When you are stuck.

## Findings — Part A (BUILD_PLAN 0.1–0.17)

**16 of 17 PROVEN by re-run.** Three defects found; all three fixed and
re-proved on this branch:

- **F1 · 0.3 — FIXED** (`4869b62`). `.githooks/pre-push` reads
  `git rev-parse --abbrev-ref HEAD` and compares that to `develop`, so it
  guards the _checked-out branch name_ and not the refspec.
  `git push origin HEAD:develop` from a feature branch is never refused —
  reproduced; the hook went straight into `make check`. Live now that `origin`
  is a real remote. Fix: read the refs git feeds pre-push on stdin and reject
  any `remote_ref` of `refs/heads/develop` or `refs/heads/main`. Patch ready at
  Re-tested after landing: `HEAD:develop` and `HEAD:main` refused, a feature
  push still reaches `make check`, a manual run still falls back to the
  checked-out branch. The push of this branch was the first live exercise of
  it.
- **F2/F3 · 0.6 — FIXED** (`5486d28`, `c14a36d`). Was UNPROVEN. The ticked proof streamed
  `/api/crawler/__smoke/sse`, which does not match the Caddyfile's
  `handle /api/crawler/runs/*/events`. The gaps were real but came from the
  general `handle /api/crawler/*`; neither the rule **order** nor
  `flush_interval -1` — the two lines the Caddyfile's own comment calls
  load-bearing — was exercised. No run sent `Accept-Encoding` either, so
  `encode zstd gzip` was never in the path, and a browser always puts it
  there. Fix: move the smoke route to `/api/crawler/runs/__smoke/events` and
  re-measure with and without compression. **Both held.** The route moved to
  `/api/crawler/runs/__smoke/events`; `encode` now carries an
  `@compressible not path /api/crawler/runs/*/events` matcher. Measured on
  Caddy v2.11.7: six frames at 1.00–1.01 s direct, through the edge, and
  through the edge with `Accept-Encoding: gzip, zstd` negotiated and declined
  (`Content-Type: text/event-stream`, `Transfer-Encoding: chunked`, no
  `content-encoding`). The original tick measured a path that bypassed both
  load-bearing lines and so proved neither.

  A third thing fell out of this and is worth knowing beyond the audit:
  **editing `docker/Caddyfile` has no effect on a running stack.** The file is
  a read-only bind mount, Caddy does not watch it, and `docker compose up -d
edge` is a no-op when only the file's contents changed. `caddy reload` or a
  restart is required. The harness now validates and reloads before probing.

- **F4 · 0.16 — FIXED** (`4869b62`). Was incomplete. `check.yml` never runs `make verify-grants`, makes
  no SSE assertion, and does not re-run `make migrate` after `migrate-down` —
  so the two proofs BUILD_PLAN singles out as costing a day each had no
  regression guard, and 0.13's cycle was half-covered. `check.yml` now runs
  `make migrate` again after `migrate-down`, `make verify-grants`, and an SSE
  step that asserts on arrival gaps with `Accept-Encoding` set — the exact
  hole F3 hid in.

**0.17 is the one left, and it is not scriptable.** The artefacts are present
(`.tasks/chore-0.17-hello-slice.md`, the `a90d1c2` merge). Whether the handoff
still works is only answerable by running a slice, which is phase 1's first
task — so it resolves itself rather than standing as a gap.
