# 005 — HTTP API and SSE

**Phase 3** · depends on 001–004 · ADR-0012, ADR-0013, ADR-0015

FastAPI with Pydantic v2 models. The OpenAPI schema FastAPI derives is the
machine-readable contract; this document is the prose one. **Changing a shape
here means regenerating frontend types** (`make types`) or the build fails.

No authentication — single user, bound to localhost.

**Every path below is served at `/api/crawler/*` through the edge** (spec
010 §2). Inside the container the app mounts them at `/api/crawler` too, so
there is no path rewriting to reason about. The BFF's endpoints live at
`/api/ui/*` and are specified separately in [spec 011](011-bff.md).

---

## 1. Conventions

- JSON in, JSON out. `snake_case` field names; the generated TypeScript keeps
  them, so there is no mapping layer to drift.
- Timestamps are RFC 3339 with offset. Money is a decimal **string**, never a
  float, with a separate 3-letter currency.
- List endpoints take `limit` (default 50, max 500), `cursor`, and endpoint-
  specific filters. They return `{items, next_cursor, total}`.
- Mutations return the mutated resource.
- Errors use RFC 7807 problem detail:

```json
{ "type": "https://spydra.local/errors/template-not-verified",
  "title": "Template has unverified selectors",
  "status": 409,
  "detail": "2 of 7 fields failed deterministic verification.",
  "fields": ["supplier_ref", "images"] }
```

Domain exceptions raised in `domain/` are translated to problem details in
`api/`; HTTP concepts do not leak inward.

## 2. Endpoints

### Domains

```
GET    /api/domains                 ?state=&render_mode=&q=&sort=health_asc
GET    /api/domains/{id}
POST   /api/domains                 {host, render_mode?, crawl_delay_ms?}
PATCH  /api/domains/{id}            partial: state, crawl_delay_ms,
                                    asset_concurrency, render_mode, max_depth,
                                    deny_patterns, user_agent, respect_robots
POST   /api/domains/{id}/pause
POST   /api/domains/{id}/resume
POST   /api/domains/{id}/crawl      start a single-domain run
GET    /api/domains/{id}/robots     cached robots.txt + effective delay
GET    /api/domains/{id}/activity   ?limit=  state transitions, backoff events
```

`sort=health_asc` is the **default** on the list endpoint. The healthy domains
need nothing; the degrading ones are why the screen was opened.

`health` is the 7-day rolling share of a domain's pages passing validation,
computed in SQL, plus a seven-point series for the sparkline.

### Seeds

```
POST   /api/seeds                   {url, category?, max_depth?, page_kind?}
POST   /api/seeds/csv/preview       multipart → parsed rows + per-row validation
POST   /api/seeds/csv/commit        {upload_id}  enqueue the accepted rows
GET    /api/seeds/template.csv      the downloadable column template
```

Preview and commit are **separate calls on purpose**: nothing enqueues until
the operator confirms. Preview returns:

```json
{ "upload_id": "u_01J…",
  "accepted": 5, "rejected": 2,
  "rows": [{"line": 1, "url": "...", "category": "O-rings", "max_depth": 5,
            "domain": {"host": "helix-seals.com", "state": "discovered", "is_new": true},
            "ok": true, "message": "OK"},
           {"line": 4, "url": "htp://...", "ok": false,
            "message": "Malformed scheme"}] }
```

### Templates

```
GET    /api/templates               ?domain_id=&is_active=&awaiting_review=
GET    /api/templates/{id}
POST   /api/templates               hand-authored
PATCH  /api/templates/{id}          edit a draft (never an approved version)
POST   /api/templates/{id}/propose  request an LLM proposal     → 202
POST   /api/templates/{id}/test     {sample_urls?} run against samples
POST   /api/templates/{id}/dry-run  discovery preview (spec 004 §4)
POST   /api/templates/{id}/approve  → new version, is_active, domain → active
POST   /api/templates/{id}/reject   {note}
POST   /api/templates/batch-approve {template_ids: [...]}
GET    /api/templates/{id}/diff/{other_id}
```

`POST /test` returns the matrix the review screen renders:

```json
{ "fields": {
    "title":        {"selector": "h1.product-title", "match_count": 1,
                     "resolved": "Zirconia Flap Disc 115 mm · 120 grit",
                     "confidence": "high", "verified": true},
    "supplier_ref": {"selector": "dl.meta dd:nth-of-type(3)", "match_count": 1,
                     "resolved": null, "confidence": "low", "verified": true,
                     "warning": "empty on 2 of 5 samples"} },
  "samples": [
    {"url": "…/flap-disc-120g-115mm", "score": "7/7",
     "results": {"title": "pass", "price": "pass", "supplier_ref": "pass"}},
    {"url": "…/SKU-8841", "score": "6/7",
     "results": {"title": "pass", "supplier_ref": "fail"}} ] }
```

`batch-approve` exists from phase 3, not as a later addition — see ADR-0005
and `docs/SCREENS.md` §4.

### Runs

POST   /api/runs/{id}/pause

```

### Unknown pages

```
GET    /api/unknown-pages           ?reason=&domain_id=  grouped by default
GET    /api/unknown-pages/groups    {domain, reason, url_pattern, count, first_seen}
POST   /api/unknown-pages/retry     {group_ids: [...]}
POST   /api/unknown-pages/dismiss   {group_id}  adds a deny_pattern to the domain
GET    /api/unknown-pages/{id}/html the retained snapshot, within TTL
```

Dismiss **adds a deny pattern**. Without that the same URLs reappear every run
and the inbox becomes noise the operator stops reading.

### Pages and observations

```
GET    /api/pages                   ?domain_id=&category=&validation=&q=
                                    &price_min=&price_max=&seen_since=
GET    /api/pages/{id}
GET    /api/pages/{id}/observations  ?limit=
GET    /api/pages/{id}/diff?a={obs}&b={obs}
```

Every observation in a response carries its `template_id` and version. That is
what distinguishes a site change from the operator's own selector edit
(ADR-0006) and it must not be omitted from list responses "to save bytes".

GET    /api/reports/politeness          ?run_id=
GET    /api/reports/coverage
{any}&format=csv|json
```

### Health

```
GET    /api/crawler/healthz
{ "db": "ok",
  "render": "ok",            // the sidecar (spec 012)
  "llama_server": "down",    // the host process (ADR-0009)
  "disk_free_bytes": 65970503680,
  "version": "0.1.0" }
```

Backs the sidebar footer. **A degraded dependency is still a 200.** The API
is fine; a path through it is not. `llama_server: down` blocks onboarding
(ADR-0005); `render: down` blocks `rendered` domains (ADR-0016). Returning
503 here would make the healthcheck fail and take the service out of
rotation for a condition it can do nothing about.

## 3. SSE

```
GET /api/runs/{run_id}/events   →  text/event-stream

id: 1041
event: progress
data: {"domain":"example.com","queued":412,"in_flight":2,"done":180,"failed":3}

id: 1042
event: page
data: {"url":"...","status":200,"strategy":"selector","fields":7,"ok":true}

id: 1043
event: domain_state
data: {"domain":"calder-industrial.co.uk","state":"paused","reason":"three_403s"}

id: 1044
event: assets
data: {"queue_depth":2204,"in_flight":18,"dedupe_rate":0.31}

id: 1045
event: run_state
data: {"state":"completed","stats":{...}}
```

- Every event has a monotonic `id` from `run_events.seq`.
- On reconnect the browser sends `Last-Event-ID`; the server **replays from
  `run_events` then continues live**. A slept laptop sees no gap.
- `run_events` is retained for the run plus 7 days, then purged with the run's
  HTML snapshots.
- Heartbeat comment every 15 s so proxies do not close an idle stream.
- `progress` events are coalesced to at most one per domain per second. A
  busy run otherwise emits thousands of events the UI cannot use.

## 4. Acceptance

- [ ] OpenAPI schema generates TypeScript with no `any`.
- [ ] `make types` produces no diff on a clean tree.
- [ ] CSV preview never writes to `crawl_queue`; commit does.
- [ ] Approving a template creates a new version and leaves the prior readable.
- [ ] Reconnecting to an SSE stream with `Last-Event-ID` replays missed events
      in order, exactly once.
- [ ] Killing the API mid-stream and reconnecting loses no events.
- [ ] Every list endpoint paginates and every filter is exercised by a test.
- [ ] `GET /api/health` reports `llama_server: down` with a 200 when the host
      process is absent.
