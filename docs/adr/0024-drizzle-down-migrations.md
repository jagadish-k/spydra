# ADR-0024 — `ui` down-migrations: hand-written `down.sql`, run by a ledger-aware script

**Status:** Accepted · 2026-10-15
**Context:** phase 0 · task 0.10 · extends [ADR-0021](0021-drizzle-for-bff.md) §3

---

## Context

ADR-0021 requires `generate + migrate` for the `ui` schema precisely because
`push` has "no artifact to review, no down path", and `make migrate-down` is
part of the test suite. The assumption inside that sentence is that the
chosen tool can downgrade. It cannot: **`drizzle-kit` 0.31.x has no downgrade
command** (verified: `generate, migrate, introspect, push, studio, up, check,
drop, export` — `drop` removes named tables interactively, which is not a
down-migration). Alembic has had `downgrade` since forever; Drizzle's
maintainers have repeatedly declined to add one, on the grounds that
down-migrations should be reviewed rather than generated.

Meanwhile CI must prove `make migrate-down` works for **both** chains
(`docs/WORKFLOW.md` §2, `docs/DEVELOPMENT.md` § Commands), and BUILD_PLAN 0.10
requires "one trivial `ui` table proving generate → migrate → migrate-down".

## Decision

1. Every migration generated by `drizzle-kit generate` is committed together
   with a **hand-written sibling `down.sql`** in the same directory:
   `bff/drizzle/0000_example.sql` ← generated, never edited
   `bff/drizzle/0000_example.down.sql` ← written by the author of the change
   The down file is part of the reviewable artifact — which is the property
   ADR-0021 wanted and `push` cannot offer.
2. `bff/src/db/migrate-down.ts` (~50 lines, runs via `npm run migrate:down`,
   wired into `make migrate-down-ui`):
   - reads Drizzle's ledger table (`drizzle.__drizzle_migrations`) and
     `bff/drizzle/meta/_journal.json`;
   - resolves the **last applied** migration by journal timestamp;
   - executes its `down.sql` inside a transaction;
   - deletes the ledger row on success.
     One step back, exactly like `alembic downgrade -1`. Not a downgrade-to-
     arbitrary-version tool — `ui` has four tables and a linear history; the
     simple thing is the correct thing here.
3. A test asserts **every migration directory under `bff/drizzle/` has a
   `down.sql`**, so a generated migration cannot land without its down path.
   This joins the two existing guards (spec 010 §3 grants, `schemaFilter`) as
   the third place the same boundary is enforced.

## Consequences

- `make migrate-down` genuinely works for both chains; CI can prove it.
- Down migrations are written by hand, under review, in the PR that also
  carries the generated up migration — the reviewer sees both directions.
- **Cost:** a second file per migration and ~50 lines of runner to maintain.
  At four tables and a linear history this is cheap; if `ui` ever grows
  branching histories, revisit with intent rather than extending this script.
- `drizzle-kit` version bumps may change the journal format; the runner reads
  it defensively and fails loudly on an unknown shape rather than guessing.

## Alternatives rejected

| Option                                                 | Why not                                                                                                                                |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `drizzle-kit push` when a down path is needed          | The exact thing ADR-0021 forbids: no artifact, no review, no reproduction                                                              |
| Drop the `migrate-down` requirement for the `ui` chain | CI would prove downgrades for one chain only; the requirement exists because a schema change nobody can roll back is a trap            |
| Derive `down.sql` automatically (reverse the SQL)      | Works for `CREATE TABLE`, silently wrong for `ALTER … ADD COLUMN` with `NOT NULL DEFAULT`, data migrations, and everything interesting |
| A different Node migration tool for `ui`               | Splits one schema's toolchain in two; ADR-0021 already weighed the alternatives                                                        |
