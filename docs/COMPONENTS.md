# Spydra — component catalog

**What exists in Figma, what each is used by, and what `UI_STATES.md` §3 still
asks for.** Generated by reading the Figma file, not by reading the specs — so
where this file and a spec disagree, this file describes reality and the spec
describes intent.

Figma file [`GeJPFXY4CicHBdzLMyXG2E`](https://www.figma.com/design/GeJPFXY4CicHBdzLMyXG2E/Spydra),
page `🧩 Components` (`3:138`). Screens are page `🖥 Screens` (`3:139`); the
registry is [`SCREENS.md`](SCREENS.md).

**39 components exist — 32 variant sets (196 variants) and 7 singletons.**
`UI_STATES.md` §3 asks for 51. The arithmetic between those numbers is §3
below, and it is not a simple subtraction, because five components exist under
a different name than the spec gives them.

## 2. Defined but never instanced

Nineteen of the 39 appear in no screen frame.

| Component                                               | Why that is fine                            |
| ------------------------------------------------------- | ------------------------------------------- |
| `Logo/Mark` · `Logo/Favicon` · `Logo/Lockup horizontal` | export assets and the Cover; not app chrome |

Everything else on the list is **a component the screens need and hand-build
instead**, which is the finding that matters for phase 3:

| Component                         | The screen region that hand-builds it                         |
| --------------------------------- | ------------------------------------------------------------- |
| `Table row` · `Table header cell` | screens 1 · 5 · 7 · 8 — `7:2` draws `row/…` and `th/…` frames |
| `Pagination`                      | the same four tables                                          |
| `Nav item`                        | inside `App shell/Sidebar`, drawn flat                        |
| `Segmented control`               | screen 4's Preview · Select · Skeleton switch                 |
| `Screenshot viewport`             | screen 4's left pane and the Playground canvas                |
| `Chat message`                    | screen 10's transcript                                        |
| `Log row` · `Domain card`         | screen 6's log pane and per-domain strip                      |
| `Toast`                           | the approve-submitting feedback in §4 of `UI_STATES.md`       |
| `Select` · `Toggle` · `Checkbox`  | the table filters and bulk-selection                          |
| `Card`                            | screen 8's card view                                          |
| `Icon` · `Kbd`                    | chrome glyphs and the `[` / `]` hints                         |

**This is the one thing to carry into phase 3.** `3.9` exists so that "screens
compose rather than improvise", and the Figma screens improvised sixteen
components that the library already has. A developer who builds screen 1 by
reading frame `7:2` will hand-roll a table row, because that is what the frame
shows. **Build from §1's component, not from the screen's drawn frame**, and
treat a disagreement between the two as the frame being behind.

Absence of an instance is evidence the frame hand-built the component — it is
not evidence the component is wrong. Nothing here needs redrawing before
phase 3; it needs reading in the right order.

## 4. Tokens

Variables are file-level in Figma and survive page changes. Five collections:

| Collection   | Modes        | Variables |
| ------------ | ------------ | --------: |
| `Primitives` | Value        |        55 |
| `Color`      | Light · Dark |        43 |
| `Spacing`    | Value        |        10 |

`Color` is the only collection with a Dark mode, which is correct: spacing,
radius and type do not change with the theme. `DESIGN_SYSTEM.md` is
authoritative for the token names; this table is only the count, so that a
missing collection is visible.
